# Security Reports

Ultimate Gshop is currently a preview. There is no guaranteed response time or stable security-support window; fixes are developed on the active modernization branch and eventually distributed through validated releases.

For a suspected vulnerability, use GitHub's private vulnerability reporting option if it is enabled for the repository. Otherwise, use a private contact method made available by a maintainer on GitHub. Do not publish exploitation details, credentials, or private server files in a public issue while a report is being assessed.

Include the affected version or commit, operating system, reproduction steps, expected impact, and a minimal shareable fixture when possible. Ordinary compatibility bugs without a security impact can use the bug-report issue template.

Before distributing a public preview, maintainers should enable and verify private reporting, document the supported release range, and replace this preview policy with the actual maintenance commitment.
